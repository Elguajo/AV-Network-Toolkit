# Исходная идея AV Network Toolkit

Дата саммари: 31 октября 2026 года. Источник: [переписка «Программы для сетевых пресетов»](https://chatgpt.com/share/6ae62d24-ae94-83eb-b48d-2806b543d5c8). Изучены текстовые сообщения опубликованной переписки; внешние вложения и программы из сравнений отдельно не проверялись.

## С чего всё началось

При работе с AV-оборудованием приходится постоянно менять настройки Ethernet ноутбука под разные подсети. Исходный запрос — создать несколько именованных пресетов IP, маски и шлюза, быстро применять нужный пресет и сохранять настройки в JSON рядом с файлами конкретного проекта. В обсуждении в полный набор параметров вошли DNS и возврат к DHCP.

Основная ценность программы — сократить повторный ручной ввод при пусконаладке и обслуживании Extron, Woxcon, DSP, сенсорных панелей и другого оборудования. Переносимый файл проекта должен позволять вернуться на объект и использовать подготовленные настройки.

## Как развилась идея

Сначала обсуждался выбор готовой Windows-утилиты. Среди кандидатов были Network Profile Manager, NetProfile Switcher и другие проекты. Затем рассматривалась доработка AV Network Toolbag, но окончательно владелец выбрал **форк Network Profile Manager с постепенным добавлением AV-инструментов через Codex**.

В переписке выбор объяснялся наличием нужных сетевых профилей, JSON, диагностики и основы на C#/.NET/WPF, а также MIT-лицензии. AV Network Toolbag стал ориентиром для Link-Local, mDNS, временного DHCP и диагностики адаптеров. Его код и ресурсы не предполагалось копировать: отсутствие объявленной лицензии было зафиксировано как ограничение.

Сравнения возможностей сторонних программ в старой переписке — исторический контекст выбора, а не актуальная проверка их версий и поведения.

## Два связанных раздела

**Network Profiles** хранят параметры сетевого адаптера ноутбука: IPv4, маску, шлюз, DNS и режим Static/DHCP. Применение выполняется к явно выбранному адаптеру. IP ноутбука и IP целевого устройства — разные данные.

**Device Web Interfaces** хранят каталог оборудования проекта: понятное имя, тип/производителя, IP, полный URL и необязательную связь с сетевым профилем. Владелец отдельно попросил такие пресеты для открытия TouchPanel и других устройств в браузере.

Нужно сохранять весь адрес: протокол, порт, путь, query и fragment. Одного IP недостаточно для интерфейса с глубокой ссылкой. К одному сетевому профилю можно привязать много ссылок; для одного устройства могут понадобиться отдельные страницы управления, администрирования и диагностики. Конкретная модель таких записей определяется спецификацией.

В обсуждении предложены два отдельных действия:

- **Open Web Interface** — открыть сохранённый URL без изменения сети.
- **Apply & Open** — явно выбрать адаптер, применить связанный профиль, проверить фактическую конфигурацию и затем открыть URL. Предусмотреть UAC, ошибки и восстановление поддерживаемого исходного состояния.

Открытие проекта или выбор устройства сами по себе не должны менять сеть. Успешное применение настроек не доказывает доступность устройства; наличие истории не гарантирует полный откат при любом сбое.

## Рабочий сценарий

1. Открыть JSON из папки AV-проекта.
2. Выбрать профиль нужной подсети и целевой Ethernet-адаптер.
3. Отдельной командой применить настройки и проверить результат.
4. Открыть сохранённый веб-интерфейс оборудования либо использовать Apply & Open.
5. При необходимости выполнить диагностику; завершив работу, явно восстановить поддерживаемые настройки или вернуться к DHCP.

Существующие профили, импорт/экспорт, сканер, Ping, история, восстановление и трей должны сохраняться при расширении программы.

Владелец также попросил зафиксировать задания и контекст в файлах, чтобы агент мог продолжать работу между сессиями. Поэтому в план вошли постоянные инструкции, спецификации, задачи, статус, решения и поэтапная приёмка. Архив из переписки содержал план, а не готовую программу.

## Границы замысла и последующие уточнения

Программа помогает настроить подключение и открыть интерфейс оборудования. Полноценное программирование устройств, автоматическая авторизация, построение физической топологии и гарантированное обнаружение всех устройств в этот план не входили. Пароли не сохраняются в проектном JSON; предупреждения TLS автоматически не обходятся. Временный DHCP требует отдельного явного запуска и изоляции.

В переписке использовалось рабочее название **AV Network Manager**; текущее утверждённое название — **AV Network Toolkit**. Первоначальное предложение работать через отдельные ветки позднее заменено владельцем на работу непосредственно в `main` (ADR-017). Примеры JSON из переписки концептуальны: действующий формат задают [спецификация проекта](spec/PROJECT_JSON_SPEC.md) и [схема](../schemas/project.avnet.schema.json). Частные адреса и ссылки устройств в это саммари не перенесены.
