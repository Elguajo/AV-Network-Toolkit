**Keep equipment passwords with a project and bring local data into one folder.**

This Preview adds optional device passwords and an explicitly confirmed copy of local profiles, settings, history and recovery journals into your user folder. Existing network tools and deliberate Apply / Apply & Open actions remain available.

> **Before upgrading:** passwords are readable in project JSON and backups. Older builds cannot open password-bearing v2 projects or see later changes in the new local-data folder. Keep your original files and an independent way to restore network settings.

## Highlights

- **Optional device passwords:** enable Save password in project file, then use separate Show/Hide, Copy and Remove actions. Values are hidden by default. Copy attempts conditional cleanup after 30 seconds and on exit; clipboard history or other applications can retain copies.
- **Preserved project originals:** the first password-bearing save requires a new, unused v2 filename. Your v1 project remains unchanged; subsequent v2 saves retain v2 even after the last password is removed. No automatic device login is added.
- **One local-data folder:** first use offers to copy existing data into `%USERPROFILE%\.av-network-toolkit`, with verified independent backups in `%USERPROFILE%\.av-network-toolkit-backups`. Originals remain in place. Conflicting, damaged or unavailable storage stops startup with recovery guidance rather than creating an empty replacement.
- **Safer preference writes:** application and scanner settings preserve damaged originals, unknown keys, backups and concurrent-change detection.

Settings also contains the new Application updates interface. **Automatic checks, downloads and installation are unavailable in this build because production signing trust is not configured.** Update manually from GitHub. Signing-key setup, release integration and native installer handoff remain separate work; no test key or unsigned fallback is included.

## Upgrade and data compatibility

1. Back up local profiles/settings/history, recovery journals and explicit project JSON files.
2. Use **Exit** in the tray menu and close all other copies. Closing the main window alone can leave the app running.
3. Run the installer, or extract the full ZIP into a new folder. Launch the first migration as an ordinary Windows user, not as administrator.
4. Review the displayed source, destination and backup paths. Choose **Copy and use new folder** to proceed, or Exit to leave the old dataset active for older builds.

Installer and ZIP share the same per-user data folder; portable does not mean USB-local settings. Migration requires an NTFS destination. Project files, exports and disposable update downloads stay at their existing locations. Originals, independent snapshots, journals and partial copies are retained; manage their disk usage and access manually.

Older builds continue using `%LOCALAPPDATA%\NetworkProfileManager` and do not see later home-folder edits. There is no automatic merge, reverse migration or downgrade synchronization. If an older build changes its dataset, the new app requires explicit acknowledgement before continuing with home data. Keep the preserved v1 project if you need old-version project access; never share v2 files or their backups with people who should not receive the passwords.

## Known limitations

- **Preview acceptance:** actual first-use migration on personal data, physical disk/power-loss recovery, pristine Windows-client deployment, cross-version installer upgrades and native updater/UAC/second-instance behavior remain unverified. Hosted package checks and synthetic fault injection do not establish these guarantees.
- **Network changes:** complex/unknown/managed settings, multiple addresses, static automatic DNS, /31–/32 and initial no-lease/APIPA states remain blocked. Old history lacks a complete original snapshot; journal-backed recovery is best effort and DHCP recovery restores policy, not the previous lease. Keep the [supported-state contract](https://github.com/Elguajo/AV-Network-Toolkit/blob/v1.1.6/docs/spec/AUDIT_FIXES_CONTRACT.md).
- **Native behavior:** real NIC/UAC/IPC/DAD, route/DNS recovery, multicast, physical egress, native clipboard/history, Narrator, actual 150%/200% and mixed-monitor scaling still need isolated acceptance.
- **Scope:** no temporary DHCP server, USB-local data, automatic device login or TLS bypass. Opening a project/device, saving or revealing a password never applies network settings.
