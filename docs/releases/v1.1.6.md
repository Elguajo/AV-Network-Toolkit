> **Before upgrading:** passwords are readable in project JSON and backups. Older builds cannot open password-bearing v2 projects or see later changes in the new local-data folder. Keep optional equipment passwords with an AV project and bring local profiles, preferences, history and recovery journals into one user-home folder. This update builds on corrected **1.1.5** and keeps deliberate Apply / Apply & Open behavior.

## ✨ Highlights

### Keep an equipment password with its project

Explicitly enable **Save password in project file**, then use separate Show/Hide, Copy and Remove actions. Values are hidden by default. The first password-bearing save requires a new, unused **v2** filename, preserving the v1 original; later v2 saves stay v2 even after the last password is removed. No automatic login or login field is added.

Passwords are plaintext in JSON/backups. Copy attempts conditional cleanup after 30 seconds and on exit, but clipboard history or other applications may retain copies. Share password-bearing files only with intended recipients.

### Move local data with a deliberate, verified copy

On first use, review a copy to `%USERPROFILE%\.av-network-toolkit`, with independent verified snapshots in `%USERPROFILE%\.av-network-toolkit-backups`. Originals stay in place. Conflicting, damaged or unavailable storage stops startup with recovery guidance instead of silently creating an empty replacement.

Installer and ZIP use the same per-user location. Explicit projects, exports and disposable update downloads stay where they were; this is not USB-local storage.

## Fixes & improvements

- **Preference saves:** application/scanner settings preserve damaged originals, unknown keys, backups and concurrent-change detection.
- **Credential boundaries:** opening a device, saving/revealing a password and opening a project never apply network settings; passwords do not add automatic login or TLS bypass.
- **Update interface:** Settings includes Application updates, but **automatic checks, downloads and installation are unavailable in this build** because production signing trust is absent. There is no test-key or unsigned fallback; use manual downloads.
- **Integrated guidance:** update copy describes the new user-home storage. Test/runner synchronization corrections retain the original assertions; they are not new device/network behavior.

## 🔄 Updating

1. Back up local profiles/settings/history, private recovery journals and explicit project JSON files.
2. Use **Exit** in the tray menu and close all other copies. Closing the main window alone can leave the app running.
3. Run the installer, or extract the complete ZIP into a new folder. Launch first-use migration as an **ordinary Windows user, not administrator**.
4. Review source, destination and backup paths. Select **Copy and use new folder** to proceed, or Exit to leave the old dataset active for older builds.

**Your data:** migration requires an NTFS destination. Originals, independent snapshots, journals and partial copies are retained; manage disk usage/access manually. Older builds continue using `%LOCALAPPDATA%\NetworkProfileManager` and do not see later home-folder edits. There is no automatic merge, reverse migration or downgrade synchronization. If an older build edits its data, the new app requires explicit acknowledgement before continuing with home data. Uninstall retains user data; keep independent backups regardless.

V1 projects remain usable through the strict v1 format. Password-bearing v2 files require this newer reader and are never automatically downgraded; keep the preserved v1 original for older builds. A removed last password does not turn a v2 file back into v1.

## Known limitations

- **Network operations:** explicitly select the intended adapter and review current/requested values. Complex/unknown/managed settings, multiple IPv4 addresses, static automatic DNS, /31–/32 and initial no-lease/APIPA states remain blocked by the shared local/project Apply contract; profiles remain editable. Empty DNS in local static input leaves DNS unchanged, while an empty gateway removes the supported default gateway after review. Project static-DNS profiles require valid explicit DNS.
- **Recovery:** newer history requires its exact valid, matching recovery journal; missing/mismatched journals block full recovery. Older history only offers its warned address/DHCP-policy restore. Recovery is separately confirmed, non-atomic and can fail. DHCP recovery restores policy, not the previous lease. Keep independent recovery.
- **Migration/install:** actual personal-data migration, physical-disk/power-loss recovery, pristine Windows-client deployment, historical cross-version upgrades and native updater/UAC/second-instance handoff remain unverified. Synthetic fault injection and hosted checks do not establish those guarantees.
- **Native behavior:** real NIC/UAC/IPC/DAD, DNS/route recovery, probes/multicast/physical egress, driver topology, clipboard/history, Narrator/touch, actual 150%/200% and mixed-monitor scaling still need isolated acceptance. Source/route predictions do not prove egress; TCP does not certify HTTP/TLS.
- **Scope:** no temporary DHCP server, USB-local settings, automatic device login or TLS bypass. Production updater key custody, signing/release integration and native installer handoff remain separate work; installing this build does not activate automatic updates.
