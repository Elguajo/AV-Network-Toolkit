> **Release status: Preview.** Native networking/recovery and clean-client acceptance remain incomplete. The .NET 10 transition also changes the applicable Windows support matrix.

This update to **1.1.1** strengthens how local profiles are applied and saved. Review the intended network change before confirming it, keep recoverable supported DNS policy, and retain your data and edits when a save fails.

## ✨ Highlights

### Review local changes before they run

Local, manual, hotkey and tray Apply/Revert now use the typed workflow already used for project changes: adapter identity checks, current/requested review, confirmation, an original snapshot and observed-state verification. Unsupported states are blocked instead of falling back to unsafe inherited mutation.

### Keep supported recovery information with history

New local history entries refer to the exact original journal, including supported DNS policy. Healthy recovery entries remain available alongside damaged files, with an unreadable-file count and additional pages beyond 1000 files.

### Preserve saved data and unfinished edits

Local profile/history saves use atomic replacement, unique backups and conflict detection. Damaged originals and backups are retained. Add/Edit keeps the draft open on save failure, and collections change only after persistence succeeds.

## Fixes & improvements

- **Migration:** failed legacy copies can be retried instead of prematurely marking migration complete.
- **Current profile:** main and tray matching agree on secondary DNS and missing-evidence rules.
- **Appearance:** Light/Dark changes refresh owned and nested windows and stale background fallbacks.
- **Privileged execution:** the old generic file-based worker is retired; its command-line switch rejects all invocations.
- **Runtime:** application, tests, rendering and packaging move to **.NET 10 LTS**. The earlier 1.1.1 artifacts remain unchanged on .NET 8.

## 🔄 Updating

1. Back up local profiles, settings, history, private recovery journals and project JSON files.
2. Use **Exit** in the tray menu before installing or replacing files. Closing the main window can leave the application running.
3. Run the installer, or replace the portable application with the complete extracted package.

**Your data:** profiles/settings/history remain in `%LOCALAPPDATA%\NetworkProfileManager\data`, recovery journals in `%LOCALAPPDATA%\NetworkProfileManager\apply-recovery`, and project JSON where you save it. Uninstall retains user data. Installer and ZIP share these per-user locations; portable does not mean USB-local settings. No home-folder migration is included. Keep backups and journals securely and manage their retention manually.

Project v1 and its chosen file location are unchanged. This deliberately narrows the supported local Apply states; profiles remain editable even when Windows apply is refused.

## Known limitations

- **Network operations:** explicitly select the intended adapter and review current/requested values. Complex/unknown/managed settings, multiple IPv4 addresses, static automatic DNS, /31–/32 and initial no-lease/APIPA states remain blocked by the shared local/project Apply contract; profiles remain editable. Empty DNS in local static input leaves DNS unchanged, while an empty gateway removes the supported default gateway after review. Project static-DNS profiles require valid explicit DNS.
- **Recovery:** newer history requires its exact valid, matching recovery journal; missing/mismatched journals block full recovery. Older history only offers its warned address/DHCP-policy restore. Recovery is separately confirmed, non-atomic and can fail. DHCP recovery restores policy, not the previous lease. Keep independent recovery.
- **Validation:** Real NIC/UAC/IPC/DAD, DNS/route recovery, ICMP/TCP/multicast, physical egress and driver/topology acceptance remain unverified. Source binding and route prediction do not prove actual physical egress; TCP acceptance does not validate HTTP/TLS. Hosted Windows Server package checks do not certify a pristine Windows client or historical cross-version upgrades. Physical/USB/Wi-Fi/Hyper-V, manual accessibility and high-contrast acceptance remain pending. The existing Windows 10 build-19045 lab does not certify .NET 10 compatibility.
- **Diagnostic check:** as recorded for this version, the hide/cancel smoke test intermittently reports `Hidden diagnostic window continued sending`. Its cause/product impact was unresolved in this source; green fixture runs do not close it. Review Stop/close in isolated acceptance before relying on continuous diagnostics. Historical network-validation acceptance records also remain open.
- **Scope:** No temporary DHCP server, device-password storage, automatic device login, TLS bypass, automatic updater or USB-local data mode is shipped. Opening a project or selecting a device never applies network settings.

See the [exact compatibility/recovery matrix](https://github.com/Elguajo/AV-Network-Toolkit/blob/v1.1.2/docs/spec/AUDIT_FIXES_CONTRACT.md) and [theme evidence](https://github.com/Elguajo/AV-Network-Toolkit/blob/v1.1.2/docs/testing/WINDOW_THEME_REVIEW.md).
