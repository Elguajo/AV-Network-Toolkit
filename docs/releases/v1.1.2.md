# AV Network Toolkit 1.1.2 — Preview

Reliability and safety update to 1.1.1, including all eight audit remediations and the Light/Dark window repair. This remains a Preview with explicit native-test and compatibility limits.

## Downloads

- **Installer:** `AVNetworkToolkit-1.1.2-win-x64-setup.exe` — primary option, Program Files, Start menu shortcut and uninstaller.
- **Portable:** `AVNetworkToolkit-1.1.2-win-x64-portable.zip` — extract the complete ZIP and run `NetworkProfileManager.exe`; keep its five native WPF DLLs alongside it.
- Both bundle **.NET 10** and use the same application payload. No separate .NET/SDK installation is needed. The previous 1.1.1 release remains unchanged on .NET 8.
- `SHA256SUMS.txt` and `package-manifest.json` identify asset integrity and the exact source commit. Binaries remain unsigned.

## Changes since 1.1.1

- Local/manual/hotkey/tray Apply and Revert use the existing typed coordinator: explicit old/requested review and confirmation, durable original snapshot, adapter identity checks and observed-state verification. The generic file-based privileged command worker is retired; its old switch rejects all invocations.
- New local history refers to the exact original recovery journal, including supported DNS policy. Older entries retain an explicitly warned address-only/DHCP-policy restore. Missing or mismatched full journals block recovery; no silent fallback or complete historical-restore claim.
- Corrupt local profile/history files and existing backups are preserved. Saves use atomic replacement with unique backups and cooperative conflict detection. Add/Edit retains its draft on save failure; collections change only after persistence succeeds.
- Valid recovery snapshots remain accessible alongside damaged files, with an unreadable-file count and bounded pages beyond 1000 files. Migration retries failed copies instead of prematurely recording completion.
- Main and tray active-profile matching now share secondary-DNS and missing-evidence rules.
- Light/Dark changes refresh owned/nested windows and stale opaque fallbacks; new windows and UI capture helpers use consistent theme state.
- App, tests, render tools, publishing and CI target .NET 10 LTS. Current release source includes the screenshot gallery and prior product branding.

## Compatibility and data

Microsoft's [.NET 10 OS matrix](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md) applies: supported Windows 11 and listed Windows 10 LTSC/IoT/Enterprise versions. **Ordinary Windows 10 22H2 is not listed.** Compatibility of the existing Windows 10 build-19045 lab with this runtime is unverified. Self-contained packaging does not change OS support.

Profiles/settings/history remain in `%LOCALAPPDATA%\NetworkProfileManager\data`; private recovery journals remain in `%LOCALAPPDATA%\NetworkProfileManager\apply-recovery`. User-chosen project JSON and v1 schema are unchanged. Back up these folders and projects before updating, and exit through the tray menu before replacing files. Uninstall retains user data. Unique backups/journals can grow and need manual retention. No user-home migration or USB-local settings mode.

The shared local/project Apply contract deliberately blocks unclassified/managed DNS, custom/complex routes, multiple addresses, static automatic DNS, /31–/32 and an initial no-lease/APIPA state. Profiles remain editable; reason-specific feedback replaces unsafe inherited mutation. Static empty DNS means unchanged; empty gateway explicitly removes the supported default gateway after review. DHCP recovery restores policy, not the previous lease. Recovery is non-atomic, separately confirmed and can fail; retain independent recovery. See [the exact compatibility matrix](https://github.com/Elguajo/AV-Network-Toolkit/blob/v1.1.2/docs/spec/AUDIT_FIXES_CONTRACT.md).

## Verification and remaining limits

Publication is gated on the release workflow's build/full unit/planning tests and same-source installer/ZIP checks: bundled WPF/JSON, exact installed payload, runtime-discovery negative control, ordinary startup, locked update/uninstall rejection, same-version reinstall and user-data retention on a disposable Windows runner. Repository reports distinguish earlier local and source-pinned evidence from actual release CI results. Hosted Windows Server checks do not certify a pristine Windows client or physical networking.

- Real NIC/DAD/UAC/authenticated IPC, actual DNS/route recovery, ICMP/TCP/multicast/driver/egress, physical/USB/Wi-Fi/Hyper-V, clean-client/cross-version installer and manual accessibility/high-contrast acceptance remain unverified.
- **Known issue DOC-R01:** the WPF diagnostics smoke intermittently reports `Hidden diagnostic window continued sending` after hide/cancel. The assertion failed in the theme check and passed in the separate audit snapshot. Root cause and product impact remain unverified; later green does not close it. Review Stop/close behavior in the isolated acceptance plan before relying on it in field work.
- Historical UX-R01/P05-R01 acceptance records remain open. This Preview does not complete the development phases or claim stable/hardware-certified readiness.
- No temporary DHCP server, device-password fields, automatic login/TLS bypass, automatic updater or automatic network configuration on file/device opening.
