# AV Network Toolkit 1.1.3 — Preview

Includes all 1.1.2 audit/runtime/theme improvements plus the tray placement and adapter-list fixes completed during release preparation. Existing v1.1.1 and v1.1.2 tags/assets are retained; no tag was rewritten to include later code.

## Downloads

- **Installer:** `AVNetworkToolkit-1.1.3-win-x64-setup.exe` — primary option; Program Files, Start menu and uninstaller.
- **Portable:** `AVNetworkToolkit-1.1.3-win-x64-portable.zip` — extract the entire ZIP and run `NetworkProfileManager.exe`; keep all five WPF native DLLs beside it.
- Both bundle .NET 10 and have the same application payload. No separate runtime/SDK installation is required. Binaries remain unsigned. Verify `SHA256SUMS.txt` and `package-manifest.json`, which identify the exact source and package hashes.

## Changes since 1.1.2

- The tray menu opens above the clicked icon, using that monitor's bounds and pixel-to-DIP conversion, with edge clamping and preserved actions/style.
- Confirmed native system filters and idle built-in WAN/debug plumbing are hidden from the main/tray adapter list by default. **Show all** restores visibility. Working, virtual, disconnected and unknown adapters, saved profiles/history and edit drafts are retained; no Windows device or network component is removed or disabled.
- Refresh retains the selected adapter by GUID. Hiding/removing its target clears selection and requires a deliberate replacement instead of silently choosing another interface.
- Left-navigation brief/research is included as planning only; an icon rail or new sidebar is not implemented by this release.

All [1.1.2 audit fixes](https://github.com/Elguajo/AV-Network-Toolkit/releases/tag/v1.1.2) remain included: typed verified local Apply/Revert, original-DNS recovery journals, safe local saves and draft retention, independently paged recovery, migration retry, shared tray DNS matching, consistent Light/Dark windows and .NET 10 LTS.

## Compatibility, data and verification

Microsoft's [.NET 10 OS matrix](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md) applies. It lists Windows 11 and specific Windows 10 LTSC/IoT/Enterprise versions; **ordinary Windows 10 22H2 is not listed**. The existing build-19045 lab does not certify compatibility. Self-contained packaging does not change OS support.

Existing profiles/settings/history remain under `%LOCALAPPDATA%\NetworkProfileManager\data`, private recovery journals under `%LOCALAPPDATA%\NetworkProfileManager\apply-recovery`, and project JSON in the chosen folder. Back these up and exit through the tray before updating. Uninstall retains user data. Project v1 schema and storage locations are unchanged; no user-home migration or USB-local settings mode. Backups/journals may grow and need manual retention.

Shared local/project Apply blocks complex/unknown/managed settings, multiple addresses, static automatic DNS, /31–/32 and initial no-lease/APIPA states. Profiles remain editable. Empty static DNS means unchanged; empty gateway explicitly removes the supported default gateway after review. Old history has a warned limited restore; new history requires its exact journal. DHCP recovery restores policy, not the old lease; recovery can fail and is not atomic. [Exact compatibility contract](https://github.com/Elguajo/AV-Network-Toolkit/blob/v1.1.3/docs/spec/AUDIT_FIXES_CONTRACT.md).

Publication requires exact-source full build/unit/planning checks and disposable Windows package verification: bundled WPF/JSON/runtime, identical installed/ZIP payload, runtime-negative-control, ordinary startup, locked update/uninstall rejection, same-version reinstall and data retention. Hosted Windows Server results are separate from pristine-client/native-network acceptance.

## Known limitations

- **Preview only:** real NIC/DAD/UAC/IPC/DNS-route recovery, ICMP/TCP/multicast/egress, physical/USB/Wi-Fi/Hyper-V topology, clean-client/cross-version install and manual accessibility/high-contrast acceptance remain unverified. Phase 07 and earlier acceptance are not completed by publication.
- **DOC-R01 remains open:** diagnostics WPF smoke intermittently reports `Hidden diagnostic window continued sending` on hide/cancel. Root cause and product impact are unverified; passing runs do not close it. Historical UX-R01/P05-R01 acceptance records also remain open.
- First 1.1.2 package CI returned installer exit 7 on reinstall; named process checks and installer logs were added. The full instrumented rerun passed. The initial transient cause is unverified; checks were retained.
- Physical mixed-DPI/Explorer/auto-hidden-taskbar placement and real driver classification require manual acceptance. Unknown adapter metadata stays visible.
- No DHCP server, device-password fields, automatic login/TLS bypass, automatic updater or automatic network change on opening files/devices.
