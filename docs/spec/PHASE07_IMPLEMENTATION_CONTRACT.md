## Boundaries and implementation sequence

1. Add independent immutable diagnostic snapshots and injectable read/probe boundaries. Do not extend the apply classification, legacy stores, JSON v1, elevated worker or scanner.
2. Read all local adapter facts on explicit Refresh, using a fixed Windows PowerShell query as existing observation code does. Join by GUID/index, not display name, for identity. Use hardware/virtual/PnP facts for physical Ethernet, Wi-Fi, USB and virtual categories; preserve unknown. Hyper-V uplink means a uniquely matched enabled `vms_pp` binding on a hardware interface, not a name containing Hyper-V. Such a binding does not certify topology or an active external switch.
3. Show GUID/index/MAC, type, link/speed, all IPv4/prefix/address states, DHCP, reported DNS, active IPv4 routes including default gateway/next hop and route metric. DNS source policy and physical topology remain unknown; metrics exclude interface metric. No reachability inference from interface facts.
4. Reuse app_settings.json flat string dictionary for an optional `HideHyperVUplinks` preference, default off; no schema migration. Hide only confirmed uplinks in diagnostic selectors, leave unknowns visible, clear a hidden selection without choosing another adapter. Legacy main/tray lists remain available and no OS interface is changed. Existing best-effort settings writer and its documented legacy limitations remain; no settings rewrite on construction.
5. Share one MVVM panel between inline diagnostics/Ping and the separate Ping window. Each has its own operation state. Explicit source IPv4 selection; only Preferred non-SkipAsSource addresses offered. Refresh clears the source, retains the explicitly chosen GUID if still present, never chooses the first adapter. The legacy main navigation does not implicitly select the diagnostic adapter; the named diagnostic selector is explicit. A separate Ping window may retain the already explicitly chosen diagnostic GUID, but always clears source selection. No send on open/load/refresh/selection. Inline sends one echo; window sends up to four with one-second intervals, summary and Stop. No general CMD shell.
6. Validate target/source and immutable request; recheck GUID/index/MAC, connected state, source membership and unique source across adapters before/after resolution and after each echo. Literal IPv4 bypasses DNS. Hostnames use OS DNS (may query another NIC) and choose one IPv4 without retries/fallback. Reject unavailable/no-IPv4 source and ambiguous duplicate addresses.
7. Query `GetBestRoute` with destination/source to obtain the OS-selected interface (source is the documented interface tie-break among best routes). Query `GetBestRoute2` with that index and requested source for details; reject no route or another interface. Do not force the requested index into a route query before establishing the OS-selected path. Send `IcmpSendEcho2Ex` with the explicit source, never fall back to destination-only Ping. Recheck identity and predicted route afterward. Present requested adapter/source/target, OS-predicted route/next hop and observed ICMP responder/status/RTT separately. A result after change is explicitly unverified. No settings, metrics, routes, firewall, profile apply or Wi-Fi disable.
8. Use fake readers/resolvers/routes/ICMP/clocks where needed in unit/render tests. Review async cancellation, close and result ownership; render Light/Dark normal/minimum with existing WPF harness. Record exact outcomes, including failures, before owner review.

## Native contract and limits

Target remains .NET 8/WPF Windows 10/11, no dependency added. Microsoft sources consulted 2026-11-01:

- [Get-NetAdapter](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapter) and [Get-NetAdapterBinding](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterbinding): local adapter facts and binding enumeration. Script text is fixed, encoded, never interpolates user/project input. Query timeout 20 s; bounded stdout/stderr and parsed snapshot sizes. Unknown optional hardware/binding evidence stays unknown; primary query failure clears stale choices and reports unavailable.
- [GetBestRoute](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getbestroute), [MIB_IPFORWARDROW](https://learn.microsoft.com/en-us/windows/win32/api/ipmib/ns-ipmib-mib_ipforwardrow): choose the OS IPv4 route with source-interface tie-break; do not use its combined Metric1 as a route-only metric. Then [GetBestRoute2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getbestroute2) (requires an initialized interface index) and [MIB_IPFORWARD_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_ipforward_row2) return details/route-only metric. Index is not persistent identity. This two-query result is a prediction, not packet observation, and may conservatively block alternative paths.
- [IcmpSendEcho2Ex](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmpsendecho2ex), [ICMP_ECHO_REPLY](https://learn.microsoft.com/en-us/windows/win32/api/ipexport/ns-ipexport-icmp_echo_reply): explicit IPv4 source, synchronous native call on worker with 2 s timeout; read address/status/RTT and TTL without dereferencing data/options pointers. TTL uses the pointer-sized native layout used by the [.NET 8 Windows Ping interop](https://github.com/dotnet/runtime/blob/v8.0.0/src/libraries/Common/src/Interop/Windows/IpHlpApi/Interop.ICMP.cs); native layout/TTL acceptance remains UNVERIFIED. Both forms preserve RTT and the separate window retains four-echo summaries. Native handle/buffer released in finally.

Source selection and predicted route do not prove actual egress. Pre-check-to-send and send-to-post-check races, weak-host behavior, compartments/VPN/policy, NIC replacement and provider failures remain. Actual egress is always UNVERIFIED without isolated packet capture. Stop/close cancels DNS/delays and future sends; an already entered native call can finish within 2 s. Resolver cancellation has a 10 s budget; synchronous native interface/route reads cannot be interrupted and may exceed it. Each result retains original adapter/source/target; selection changes cannot reassign it. Close never schedules new probes or updates a disposed surface.

Native PowerShell/NIC/ICMP/route behavior, physical USB/Hyper-V topology, unplug/route races on hardware, packet capture, privilege/driver/DNS behavior, full App/tray and manual accessibility/high contrast/scaling are NOT RUN. No production-network probes or configuration changes during automated verification. Owner/native acceptance is separate from fixture evidence.
