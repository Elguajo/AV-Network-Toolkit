# Ready-made network tests — ADR-041

2026-11-01, Asia/Tashkent. Owner approved the raster concept, especially the expanding settings-style section, and explicitly requested implementation. Bounded Phase 07 follow-up NT-01, directly on main; Phase 07 remains AWAITING_REVIEW. ADR-037 safe-only verification remains in force.

## Scope and acceptance

- Rename the existing main diagnostics expander to Network tests, below profiles/manual settings. Preserve the other workspace sections. A secondary Open test window action opens the existing diagnostic window with independent operation state.
- Reuse the shared MVVM diagnostics panel, DESIGN.md resources and English localization. Compact preset selector inline; descriptive selectable cards in the separate window. Preserve reported facts, routes, optional Hyper-V filter, explicit adapter/source selection, RTT/TTL and original request association.
- Presets: Ping — 4 requests (default), Continuous Ping, TCP port check, and Ping — single request (preserves the original inline capability). Selection, expansion, refresh and opening never send probes. Only Run test sends traffic. Continuous Ping ends on Stop, closing its owner or an invalidated source/route; approximately one second between completed attempts, no overlapping probes.
- TCP checks exactly one IPv4 destination and one decimal port 1–65535 (quick choices 80/443), through a source-bound .NET 8 socket. No payload, HTTP request, TLS/login, port scan, interface fallback or network mutation. Connection accepted, refused, timed out, unreachable and unavailable are distinct; accepted does not certify a working web application or TLS.
- Reuse existing diagnostic binding/target validation and OS-predicted route checks before/after TCP. Preserve immutable requested adapter/source/target/port in results. A changed identity/route makes even a completed result unverified. Hostnames use Windows DNS and can query another NIC; literal IPv4 avoids lookup. Binding plus route checks do not prove physical egress or eliminate races.
- TCP has a three-second connection budget within a ten-second operation budget. Stop/close cancels the socket; dispose it on all paths. Existing ICMP native calls may finish within two seconds. Do not expose exception details. Reject URL/shell inputs and invalid ports before networking.
- Disable editable inputs/Refresh/Run during an operation; keep Stop reachable. Retain at most 100 Ping result rows, with whole-run attempt/reply/RTT counters independent of the retained rows. Show attempt counts rather than claiming packet capture statistics. Keep final summary on Stop; no updates or future probes after disposal. Hiding either owner stops its active test, including the existing main close-to-tray path; expanding/collapsing the section preserves the draft and does not start traffic.
- Build, meaningful fake-boundary unit tests, full isolated regression, actual WPF Light/Dark normal/minimum renders, binding/keyboard/close/expansion checks and planning validators. No App startup, actual sockets, DNS, NIC queries, UAC or live traffic during verification.

## Architecture and limits

Retain DiagnosticPingService and its public behavior. Add a small TCP service reusing its internal validators, with the existing platform for binding/DNS/route reads and an injectable TCP connector. The production connector uses Socket.Bind(localIPv4, ephemeral port), then the cancellable ConnectAsync(IPEndPoint, CancellationToken); never the hostname/multi-address overload. The shared view model owns one cancellable operation at a time and independent window peers. No dependency, persistence/schema/worker/scanner or apply support changes.

Sources checked for net8.0: [Socket.Bind](https://learn.microsoft.com/en-us/dotnet/api/system.net.sockets.socket.bind?view=net-8.0), [.NET 8 cancellable socket connection source](https://github.com/dotnet/runtime/blob/v8.0.0/src/libraries/System.Net.Sockets/src/System/Net/Sockets/Socket.Tasks.cs). Synchronous binding/route OS reads cannot be interrupted and may exceed the operation's cancellation budget. Native Windows socket routing/cancellation and physical egress remain UNVERIFIED until separately authorized isolated acceptance. DNS/traceroute presets are outside this first increment. No release, push, Phase 08 or DHCP authorization.
