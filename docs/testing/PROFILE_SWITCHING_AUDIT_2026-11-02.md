## SWITCH-03 / ADR-057 contract

The user's Windows comparison explicitly authorizes disconnected ordinary IPv4/DHCP configuration. Keep selected stable identity, explicit review/consent/UAC, exact original snapshot, typed fixed commands and pre-state comparison. No network setting changes just from opening/selecting/importing.

Known Connected=false is independent of an assigned/usable IP. For disconnected static policy, require one classified persistent manual address; allow zero matching active addresses or a matching known-state address. A single recognized Windows automatic fallback may accompany the one configured address; retain it in the journal and reject custom fallback routes. Do not treat arbitrary extra static addresses as automatic. Unknown state, active-versus-stored conflicts, ambiguous defaults, nonstandard policy and unsupported DNS stay blocked.

For disconnected DHCP, retain automatic addressing policy with no persistent manual address; classified no-address/APIPA/lease state is distinct from an active usable lease. DAD need not run while saving an offline ordinary profile; do not change its setting. The manual Link-Local action retains its own connected/DAD assignment rule.

`MatchesOfflinePolicy` compares the actual saved address/prefix, default gateway/metric, DHCP and DNS policy/list/registration with the reviewed desired fields. It does not promote Deprecated/Tentative/Invalid addresses to Preferred evidence. Static commands already use `store=persistent`; no new registry writer or command syntax is introduced. [Microsoft documents the two policy stores and address states](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-netipaddress), and [netsh persistent address/DNS configuration](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface). These sources support implementation semantics, not native execution certification.

For a browser-free action, verified saved configuration returns Complete / `OfflinePolicyVerified` with explicit reconnect/active-address-unverified text. Apply & Open returns Unverified with the same saved-policy stage and never launches while known disconnected, including when Windows retains Preferred fields. After reconnect, ordinary strict observation and deliberate retry apply. Worker failure, cancellation, journal failure and mismatched stored configuration never become offline success.

History/recovery use the original stored static address/default when active data is absent; DHCP recovery restores policy, not the former lease/APIPA. Project schemas, profile arrays, typed request version, storage root, IPv6 and unrelated NIC settings stay unchanged. Older builds can reject newly supported recovery snapshots; retain journals and use the corrected build. No claim that offline verification proves later address availability or connectivity.
